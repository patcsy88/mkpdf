# Interoperability rules

1. **One path.** Every SDK (Node.js, Python, .NET, C++, Java, Go) calls the stable C ABI (`mkpdf-ffi`, header `include/mkpdf.h`). Brief item: Node.js may use N-API and Python may use PyO3, but only as thin wrappers over the same core. Go uses CGo over the same C ABI (decision D-06). None of them may reimplement PDF behaviour.
2. **Ownership.** The library owns every object it creates. Callers release objects with the matching `*_free` function, exactly once. Passing null to a `*_free` function is a no-op. Pointers returned by the library to borrowed data (for example error messages) are valid only until the next call on the same thread, and this is documented.
3. **Handles.** Handles are opaque. No struct layouts are exposed. Strings are passed as pointer plus length in UTF-8, without a requirement for NUL termination.
4. **Errors.** Every fallible function returns an `i32` status. `0` is success. Codes are never renumbered after release. A message is available through `mkpdf_last_error_message` for the calling thread.
5. **Panics.** No panic crosses the boundary (see `rules/rust-engineering.md`).
6. **Threads.** A handle may be used from one thread at a time. Distinct handles may be used concurrently. Thread-local error state is per thread.
7. **Versioning.** `mkpdf_abi_version()` returns `(major << 16) | minor`. Bindings check it at load time and refuse a different major version. Adding functions raises the minor version. Changing or removing anything raises the major version.
8. **Header.** `include/mkpdf.h` is generated by cbindgen and checked in CI against the committed copy.
9. **Binding tests.** Each SDK has integration tests that load the built library, create a multi-page document, and check the result. Memory leaks and double-free behaviour are tested where the language runtime allows.
10. **Packaging.** An SDK ships prebuilt libraries only from CI builds that have passed all gates. SDK versions are linked to ABI versions in a compatibility table.
